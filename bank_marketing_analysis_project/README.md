# Bank Marketing Analysis — Python + SQL

## ภาพรวม
โปรเจกต์นี้ฝึกวิเคราะห์ผลการสมัครเงินฝากประจำ (`y`) โดยใช้ **Python (pandas, matplotlib/seaborn)** สำหรับตรวจคุณภาพข้อมูลและสำรวจข้อมูล (EDA) และ **SQL (SQLite)** สำหรับเปรียบเทียบผลลัพธ์ระหว่างกลุ่มลูกค้า

**Dataset:** [Kaggle Playground Series S5E8 — Binary Classification with a Bank Dataset](https://www.kaggle.com/competitions/playground-series-s5e8/data)

> ข้อควรทราบ: ชุดข้อมูลการแข่งขันนี้เป็นข้อมูลสังเคราะห์ที่อ้างอิงจาก Bank Marketing dataset ต้นฉบับ ไม่ใช่บันทึกแคมเปญจริงที่เกิดขึ้นในปี 2025 แม้การแข่งขันจะจัดในปี 2025 ก็ตาม

## วิธีเปิดและรัน
1. ดาวน์โหลด `train.csv` จากหน้า Data ของการแข่งขัน Kaggle (อาจต้องเข้าสู่ระบบและยอมรับกติกาการแข่งขันก่อน)
2. เปิด [Google Colab](https://colab.research.google.com/)
3. อัปโหลดไฟล์ `bank_marketing_analysis_colab.ipynb` เข้า Colab
4. เลือก **Runtime → Run all** หรือรันแต่ละ Cell จากบนลงล่าง
5. เมื่อระบบถาม ให้อัปโหลด `train.csv`
6. ตรวจผลทุกส่วนและบันทึกผลลัพธ์ที่ได้จริงก่อนเขียนข้อสรุปลง README

## วิธีวิเคราะห์
- **Data quality:** ตรวจชื่อคอลัมน์ ชนิดข้อมูล ค่าว่าง แถวซ้ำ และการกระจายของตัวแปรเป้าหมาย
- **Category audit:** ตรวจค่า `unknown` แยกจาก `NaN` พร้อมจำนวนและร้อยละในแต่ละคอลัมน์ข้อความ
- **EDA:** เปรียบเทียบอัตราการสมัครตามกลุ่ม เช่น อาชีพ ช่องทางติดต่อ เดือน และผลแคมเปญก่อนหน้า เมื่อคอลัมน์มีอยู่
- **Visualization:** กราฟแท่งแสดงอัตราการสมัครของแต่ละกลุ่ม โดยควรพิจารณาจำนวนข้อมูลประกอบ
- **SQL / SQLite:** คำนวณ KPI รวมและเปรียบเทียบอัตราการสมัครตามอาชีพ ช่องทางติดต่อ ระดับการศึกษา เดือน และจำนวนครั้งที่ติดต่อในแคมเปญปัจจุบัน
- **Export:** สร้าง `data_quality_report.csv` เพื่อบันทึกชนิดข้อมูล จำนวนค่าว่าง และสัดส่วนค่าว่างของแต่ละคอลัมน์

## ผลลัพธ์ที่ตรวจสอบแล้ว

การตรวจสอบทางเทคนิคของ Notebook ทำโดยรันโค้ดทุก Cell กับ **ข้อมูลทดสอบสังเคราะห์ที่สร้างขึ้นเพื่อทดสอบการทำงาน** ครอบคลุมคอลัมน์หลัก (`y`, `job`, `education`, `contact`, `month`, `campaign`) และค่า `unknown` การทดสอบนี้ใช้ตรวจว่าโค้ดทำงานครบ ไม่ใช่ผลวิเคราะห์จากชุดข้อมูล Kaggle จริง

**ตัวเลขเชิงธุรกิจจาก Kaggle ยังไม่ถูกกรอกใน README นี้** เพราะต้องรัน Notebook กับ `train.csv` ที่ดาวน์โหลดจาก Kaggle จริงก่อน ไม่ควรเดาอัตราการสมัครหรือจัดอันดับกลุ่มโดยไม่มีผลลัพธ์ที่ตรวจสอบได้ หลังรันจริง ให้เติมข้อมูลต่อไปนี้:

| ตัวชี้วัดที่ต้องบันทึก | ผลจาก `train.csv` จริง |
|---|---|
| จำนวนแถวและคอลัมน์ | เติมหลังรัน |
| สัดส่วน `y = yes` | เติมหลังรัน |
| คอลัมน์ที่มี `unknown` และร้อยละ | เติมหลังรัน |
| กลุ่มการศึกษา/เดือน/จำนวนครั้งติดต่อที่มีอัตราสมัครสูง | เติมพร้อมจำนวนระเบียน |
| จำนวนแถวซ้ำและค่าว่าง | เติมหลังรัน |

## การจัดการ `unknown`
- ตรวจสอบ `unknown` แยกจากค่าว่างจริง (`NaN`) เพราะมีความหมายไม่เหมือนกันเสมอไป
- ในการวิเคราะห์เบื้องต้นให้เก็บ `unknown` เป็นหมวดหมู่แยกไว้และรายงานสัดส่วนก่อน
- ไม่แทน `unknown` ด้วยหมวดหมู่ที่พบบ่อยที่สุดโดยอัตโนมัติ เพราะอาจบิดเบือนข้อมูล
- หากสัดส่วนสูง ให้ตรวจเอกสารชุดข้อมูลและทำ sensitivity analysis เปรียบเทียบผลเมื่อเก็บไว้กับทางเลือกอื่น โดยอธิบายเหตุผลอย่างชัดเจน
- อย่าลบแถวที่มี `unknown` โดยไม่ประเมินว่าการลบจะทำให้กลุ่มตัวอย่างเปลี่ยนไปอย่างไร

## ข้อจำกัด
- เป็นข้อมูลสังเคราะห์ จึงไม่ควรนำผลไปอ้างว่าเป็นผลจริงของธนาคารหรือแคมเปญจริง
- การวิเคราะห์เป็นเชิงพรรณนา ความสัมพันธ์ระหว่างกลุ่มกับอัตราสมัครไม่ได้พิสูจน์เหตุและผล
- ตัวแปรและความหมายขึ้นกับไฟล์รุ่นที่ดาวน์โหลด ควรตรวจ schema และคำอธิบายของ Kaggle ก่อนตีความ
- อัตราสมัครของกลุ่มที่มีจำนวนระเบียนน้อยอาจผันผวน ควรดูทั้งอัตราและขนาดกลุ่ม
- Notebook ใช้ SQLite ในหน่วยความจำเพื่อฝึก SQL ไม่ใช่ฐานข้อมูล production
- โค้ดรองรับกรณีคอลัมน์บางตัวไม่มีอยู่ด้วยการข้าม query นั้น แต่การวิเคราะห์ที่เปรียบเทียบกันได้ยังขึ้นกับคอลัมน์ในไฟล์จริง

## ข้อเสนอแนะทางธุรกิจ
1. ใช้อัตราการสมัครร่วมกับจำนวนระเบียนเพื่อเลือกกลุ่มที่เหมาะสำหรับการทดลอง ไม่เลือกจากอัตราสูงสุดอย่างเดียว
2. หากพบกลุ่มที่น่าสนใจ ให้ทดลองแคมเปญขนาดเล็กหรือ A/B test ก่อนขยายผล และกำหนดกลุ่มควบคุมให้เหมาะสม
3. วัดผลด้วยอัตราสมัคร จำนวนผู้สมัคร ต้นทุนต่อผู้สมัคร จำนวนครั้งที่ติดต่อ และผลตอบแทนที่เกี่ยวข้อง หากมีข้อมูลต้นทุน
4. ตรวจสอบผลตามเดือน ช่องทาง ระดับการศึกษา และจำนวนครั้งติดต่อร่วมกัน เพราะแต่ละปัจจัยอาจสัมพันธ์กัน
5. หลีกเลี่ยงการสรุปว่าเพิ่มจำนวนครั้งติดต่อหรือเลือกเดือนใดแล้วจะทำให้สมัครมากขึ้นจากข้อมูลเชิงสังเกตเพียงอย่างเดียว
